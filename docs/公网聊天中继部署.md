# 公网聊天中继部署

公网聊天室由 `relay/` 目录下的 Go 中继服务支撑。服务本身只监听本机端口，对外通过 Caddy 或 Nginx 提供 HTTPS。客户端不内置任何服务器地址，需要部署后把地址告诉使用者。

## 一、准备

- 一台有公网 IP 的服务器（Linux x64 或 Windows x64 均可）
- 一个域名，例如 `chat.example.com`，解析到这台服务器
- 构建需要 Go 1.26 或更高版本

中继进程只负责 WebSocket 与文件上传下载，TLS 交给反向代理。**公网聊天室必须走 HTTPS**：客户端默认按 `https://` 连接，纯 HTTP 只适合内网联调。

## 二、编译

```bash
cd relay

# Linux x64
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 \
  go build -trimpath -ldflags "-s -w" -o xlan_relay_linux_amd64 .

# Windows x64
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 \
  go build -trimpath -ldflags "-s -w" -o xlan_relay_windows_amd64.exe .
```

数据库使用纯 Go 的 SQLite 驱动，`CGO_ENABLED=0` 也能正常编译运行。

## 三、启动参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `-addr` | `127.0.0.1:43500` | 监听地址。用反向代理时保持只监听 127.0.0.1 |
| `-data` | `data` | 数据目录，SQLite、密钥与上传的文件都放在这里 |
| `-public-url` | 空 | 对外访问地址，例如 `https://chat.example.com`。填了日志里会打印完整可填写的中继地址 |
| `-key` | 自动生成 | 地址中的路径密钥，只允许字母、数字、`-`、`_`，长度 4 到 64。不填则自动生成并保存在数据目录的 `key` 文件里 |
| `-max-file-mb` | `20` | 单个文件大小上限（MB） |

示例（Linux）：

```bash
./xlan_relay_linux_amd64 \
  -addr 127.0.0.1:43500 \
  -data /srv/xlan-relay/data \
  -public-url https://chat.example.com \
  -max-file-mb 20
```

启动后日志会打印：

```
X互传 公网聊天中继已启动
监听地址：127.0.0.1:43500
访问地址：https://chat.example.com/xlan/AbCdEfGh1234567890ab
数据目录：/srv/xlan-relay/data
文件上限：20 MB
```

这条「访问地址」就是客户端要填的中继地址。

数据目录结构：

```
data/
  relay.db      SQLite 数据库（房间、成员、消息、文件索引）
  key           自动生成的路径密钥，务必保留；换了密钥等于换了地址
  files/        上传的文件，按随机 ID 存放
```

迁移或备份时整个 `data/` 目录一起复制即可。

## 四、反向代理

路径结构：

- `GET /xlan/<密钥>` 探测服务
- `GET /xlan/<密钥>/ws` WebSocket
- `POST /xlan/<密钥>/files` 上传（请求体是原始文件字节）
- `GET /xlan/<密钥>/files/<文件ID>` 下载

反向代理需要支持 WebSocket 升级（Upgrade / Connection 头），并把请求体上限调到不小于 `-max-file-mb`。

### Caddy（推荐，自动申请证书）

```caddyfile
chat.example.com {
    reverse_proxy 127.0.0.1:43500
}
```

Caddy 默认已处理 WebSocket 升级，无需额外配置。如需限制上传体积：

```caddyfile
chat.example.com {
    request_body {
        max_size 25MB
    }
    reverse_proxy 127.0.0.1:43500
}
```

`max_size` 要比 `-max-file-mb` 略大，留出请求头余量。

### Nginx

```nginx
server {
    listen 443 ssl;
    server_name chat.example.com;

    ssl_certificate     /etc/letsencrypt/live/chat.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/chat.example.com/privkey.pem;

    # 上传体积，略大于 -max-file-mb
    client_max_body_size 25m;

    location /xlan/ {
        proxy_pass http://127.0.0.1:43500;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # WebSocket 升级
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 服务端每 45 秒发一次心跳，读超时留出余量
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

Nginx 的 `map` 写法可让 `Connection` 头按情况切换，但中继的所有业务请求都在 `/xlan/` 下，直接固定 `"upgrade"` 不影响其他接口。

对外只需要开放 80/443，`43500` 不要暴露到公网。

## 五、systemd 服务（Linux）

```ini
[Unit]
Description=X互传 公网聊天中继
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/xlan-relay
ExecStart=/srv/xlan-relay/xlan_relay_linux_amd64 -addr 127.0.0.1:43500 -data /srv/xlan-relay/data -public-url https://chat.example.com -max-file-mb 20
Restart=on-failure
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now xlan-relay
sudo journalctl -u xlan-relay -f
```

服务内部已固定使用 `Asia/Shanghai` 时区，不依赖系统时区设置。

## 六、客户端填写

Windows 端与 Android 端都在「设置 → 公网聊天室 → 服务器地址」里填写日志打印的完整地址：

```
https://chat.example.com/xlan/AbCdEfGh1234567890ab
```

- 不写协议时客户端会按 `https://` 补全。
- 地址留空即关闭公网聊天室，不会尝试连接。
- 连接成功后会显示「公网广播」，可创建房间或输入六位数字房间号加入。
- 单个文件上限由服务端 `-max-file-mb` 决定，客户端会读取并在超限时拒绝发送。

## 七、升级与排障

- 升级：替换二进制文件后重启服务，`data/` 目录保持不变，房间与历史消息不会丢失。
- 日志里的访问地址不对：检查 `-public-url` 是否带上 `https://` 与域名，末尾不要加 `/`。
- 客户端一直「未连接」：确认反向代理已放通 `/xlan/` 路径、证书有效、WebSocket 能升级。
- 上传大文件失败：把 Nginx 的 `client_max_body_size`（或 Caddy 的 `request_body.max_size`）调到大于 `-max-file-mb`。
- 想换地址：修改 `-key`（或删除数据目录里的 `key` 文件让它重新生成），之后客户端要同步改成新地址。
